# 阅读清单：Store 与请求缓存

与文章《状态管理：组件状态、Store 与服务端数据》配套。React/React DOM 18.3.1，TypeScript 5.7.2，Vite 6.4.5，Node.js 22。依赖在 package-lock.json 锁定。无账号、密钥或真实后端。

```sh
cd examples/react-state-management
npm ci
npm test
npm run build
npm run dev -- --port 4303 --strictPort
```

打开终端所示地址。4303 是独立实验端口，不改变主站的 4173；已占用会明确报错。

## 文件

- `App.tsx`：完整单文件实验，包含不可变 reducer、外部 Store、请求缓存与 React 页面，可放到站点实验室。
- `main.tsx` / `index.html`：Vite 入口，不启用 StrictMode。
- `test.mjs`：纯逻辑与真实 React DOM/jsdom 行为测试。
- `VERIFICATION.md`：实际验证与未覆盖范围。

## 观察步骤

1. 初始两篇未读。点击“切换 fiber”，已读数量为1；勾选只看未读，Fiber隐藏，但已读数量仍为1。
2. 点击“读取摘要”，结果为“服务端初始摘要”；再次读取可复用成功缓存。
3. 点击“标记过期”，旧数据仍在；再次读取进入刷新、再成功。失效不会自动发请求。
4. 点击“制造响应乱序”：旧请求100ms，新请求20ms，两个都结束后必须保留“新响应”。延迟用于教学，不是性能指标。
5. 单独点击“乐观修改后失败”：立即显示乐观值，100ms后恢复先前值，仍标记待验证。交错新操作时，旧回滚应拒绝覆盖新版本。

测试将请求完成顺序用可控Promise固定，不依赖计时器快慢。

## 重要边界

清单和服务端摘要是两个独立模型，不会自动互相同步。缓存仅演示稳定快照、去重、key隔离、版本仲裁和条件回滚；没有自动重试、计时过期、垃圾回收、持久化或服务器鉴权。没有完整并发mutation协议；旧回滚被拒绝后，真实系统需要重新验证服务器数据。多个相互依赖的乐观写入应串行化或维护操作层。

代码是客户端示例，没有getServerSnapshot，不能直接声称SSR支持。实例隔离测试只验证不同工厂实例互不影响。React源码引用位于主站固定版本资料，不在此项目复制第三方源码。
